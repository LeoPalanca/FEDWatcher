\section{Project Diary}

The full GitHub commit log is the canonical record of what was done and when; what follows is a curated narrative grouped into seven phases. Author initials are used for brevity: \textbf{LP}~=~Leonardo Palanca, \textbf{SP}~=~Sebastian Pasz, \textbf{LM}~=~Lorenzo Mottinelli, \textbf{JM}~=~Johnny Magon.

\subsection{Phase 1 -- Bootstrap (April 18, 2026)}
The repository was created the same evening as a single bootstrapping burst by LP and SP. LP opened it with a placeholder README and a first round of documentation, then added a simplified architecture sketch alongside an initial HTML dashboard mockup that fixed the visual language used by every later iteration of the page. SP stood up the Python side end-to-end: the requirements and virtual-environment scaffolding, a first SQLite \texttt{test\_db.py}, an exploratory scraper sandbox, the first \texttt{MonitorAgent} prototype, an improved monitor pass, a \texttt{fetch\_doc\_text} helper, and the decision to keep the database URL out of the tracked tree. The two streams converged at the end of the day on a working ``read documents from a Fed-like source, dump them into SQLite'' loop, and the convention of writing commit messages in the Anthropic style (subject + verified-by body) was adopted immediately.

\subsection{Phase 2 -- Architecture Consolidation (April 30, 2026)}
After a pause to clarify the brief, LP rewrote the AGENTS contract and turned it into the entry point for any contributor or AI agent, then consolidated the architecture documentation into the README so that the repository had a single source of truth for ``what does which agent do''. A synthetic Fed-like static site, \texttt{FakeFed}, was deployed behind Nginx by LP as a reproducible scraper fixture independent of the live Federal Reserve website, and the homepage of \texttt{fedwatcher.ellep.it} was published as a static landing dashboard. SP did the necessary janitorial work, removing dead files left over from the bootstrap day so that subsequent agent work started from a clean tree.

\subsection{Phase 3 -- Analyst v1 and Macro Ingestion (May 5--13, 2026)}
The first end-to-end \texttt{AnalystAgent} appeared on May 5 from JM: it segments each FOMC document into rhetorical sections (assessment, outlook, policy stance, voting record) and asks an LLM to fill a structured rubric per section, then writes the result back into \texttt{sentiment}. Documentation around the analyst followed in lockstep over the next day, mostly from LM. LP added \texttt{OpenRouter} as a vendor-agnostic LLM gateway so the team could swap between Anthropic and OpenAI backends without code changes, and shipped the first FRED macro ingestion -- the \texttt{macro\_data} table and a backfill command for CPI, core CPI, unemployment and 2-year yields. Mid-May LP made the monitor source-aware so it could ingest both the live Fed site and \texttt{FakeFed} with the same code path, and extended the macro refresh to cover multiple series in a single cron pass.

\subsection{Phase 4 -- Multi-Analyst, Strategist and Automation (May 19--22, 2026)}
The team intentionally produced several competing analyst implementations to compare segmentation strategies, prompt styles and LLM backends. SP shipped two ``better analyst'' iterations that explored alternative section weights and prompts, and JM added a \emph{dual-model} analyst that runs two LLMs in parallel and reconciles their outputs; SP wired the new variant into the database the following window. The \texttt{StrategistAgent} got its first real version from LM: an EWMA-smoothed tone fed through an ordered-probit nowcast with explicit narrative output, and the divergence between tone-implied and market-implied next-rate flipped to the economically correct sign (positive means the market prices a higher next rate than the tone model). Cron-driven automation was added by SP in three pieces -- a bash wrapper layer, a 90-day rolling documents-refresh window, and a sequence of glue scripts -- and JM closed the agent loop with the final ``run-everything'' agent. LM moved the FOMC historical-page backfill (going back to 1994) into \texttt{scripts/} so that fresh installations can rebuild the full corpus reproducibly. JM then fixed a weighted-score bug where zero-weighted sections were polluting the average and biasing short or sparse documents toward neutral.

\subsection{Phase 5 -- Productionization and Ops (May 22--27, 2026)}
The static \texttt{snapshot.json} that initially powered the dashboard was replaced by LP with a live read-only FastAPI service, and the dashboard's data explorer received a legend and labels from LP to make table semantics obvious. LM backfilled the FOMC \texttt{FEDFUNDS} policy rate into \texttt{macro\_data} to unblock the strategist's tone-implied-rate calculation, and replaced the older \texttt{literature.md} with a structured \texttt{report/} directory. JM updated \texttt{db/schema.sql} to match the new multi-weights analyst variant and rewrote the README to document all four agents end-to-end.

LP closed the phase by tightening \texttt{AGENTS.md} so that any contributor -- human or AI -- must treat \texttt{db/schema.sql} as authoritative and must explicitly flag missing tables or columns rather than silently introducing them. This is a direct consequence of an operational incident on the same day, where two SQLite copies of the production database had drifted: the API was reading a complete \texttt{/opt/FEDWatcher/fedwatcher.db} while all cron writers were updating an incomplete \texttt{/home/programming/FEDWatcher/fedwatcher.db}. The two databases were merged, the live API was repointed to the cron-written copy, and the redundant \texttt{/opt} tree was archived and removed. The schema-contract commit closes the door on similar drift in the future.

\subsection{Phase 6 -- Live v2, Strategist Automation and an Accountability Experiment (May 27 -- June 2, 2026)}
On May 27 LP swapped the v1 prototype dashboard for a live v2 dashboard wired directly to the FastAPI service. The next day LM put the strategist on a cron loop so each new statement triggers a fresh signal write, and JM landed a first attempt at a publicly visible track record: an \texttt{accountability} FastAPI router exposing hit rate, mean absolute error (MAE) and Brier score over the strategist's ordered-probit signals, then mounted it in \texttt{main.py}. Two methodological issues surfaced almost immediately and were fixed by JM in a follow-up commit. First, the original code diff'd \texttt{policy\_rate} around the meeting that had just happened, but the bucket probabilities target the \emph{next} meeting, so each forecast \(S(M)\) was re-anchored to \(S(M{+}1)\) and the actual outcome was read from \texttt{FEDFUNDS} around that anchor month. Second, intermeeting and emergency statements (gap to the previous statement below 35 days) were filtered out of both the forecast and anchor positions, since they cannot fairly be graded against a model that targets scheduled meetings. LP added the academic-report draft and the dashboard footer linking it, and JM continued frontend work in parallel. On June 2 LM produced a math review of the report and fixed a typo on the homepage, and on June 3 unblocked the LaTeX build by adding \texttt{lmodern} and correcting a math-mode escape in the methods section.

\subsection{Phase 7 -- Design Pass, Deploy Refactor and Accountability Rollback (June 7, 2026)}
The final push, all on a single day, split into a design sprint and an ops sprint. On the design side LM brought a full proposal design live -- a §04 Method modal, a §05 Accountability section with KPI tiles and a recent-predictions table, additional hero-takeaway modals and a back-to-top control -- and then wired §05 to \texttt{/api/accountability} so the hardcoded placeholder numbers were replaced by live values from the FastAPI service. LP and JM repalettised the signal-divergence chart from green/red to two shades of purple, untangling the ``directional'' connotation of red/green from the tone-vs-market gap that the chart actually shows. A short-lived attempt by LM to consolidate the frontend into a single assets bundle was reverted within minutes after a regression. On the ops side LP introduced a deploy script using a restricted \texttt{programming} user and SSH connection multiplexing, and realigned the backend deploy path with the \texttt{systemd} runtime tree.

The accountability section was then \emph{removed} from production later the same day, in two commits by JM: the router was unmounted from \texttt{main.py}, and the §05 block, the navbar link and the corresponding fetch logic were stripped from the dashboard. The reason is documented in the strategist's own source: the ordered-probit \(\beta\) coefficients and cut points are explicitly flagged as ``placeholders calibrated to economic priors\ldots{} but MUST be refit on historical FOMC outcomes before being published'' (\texttt{agents/strategist.py}, lines 25--29). Publishing hit rates and Brier scores against an unfitted model would have advertised numbers that reflect prior beliefs rather than measured performance; the section is preserved in the codebase (\texttt{app/accountability.py}) so that the same metrics can be brought back online unchanged once the strategist is refit on the historical corpus. A flurry of \texttt{accountability.py} relocations during the same window (LM, then restored by JM) was part of an aborted refactor and is recorded here only for completeness.

\subsection{Tools and Workflow}
Across all phases the team relied on a small, stable toolchain: \textbf{Python 3} (FastAPI, \texttt{requests}, \texttt{beautifulsoup4}, \texttt{pandas}, \texttt{sqlite3}), \textbf{SQLite} for storage, \textbf{Nginx} and \texttt{systemd} on the VPS, and \textbf{vanilla HTML/CSS/JS} (Chart.js) for the dashboard, deliberately avoiding a frontend framework. Generative-AI tools are listed in Section~\ref{sec:ai}.
