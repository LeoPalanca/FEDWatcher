\section{Project Diary}

The GitHub commit log is the canonical record of who did what and when; this diary is the editorial layer on top of it. Rather than narrating each commit, it groups the eight weeks of work into phases, each phase framed around the question the team was trying to answer and the artefact that survived from it. Individual authorship is acknowledged where a contribution shaped the project's direction; routine commits (typos, cosmetic tweaks, in-flight reverts) are omitted. Author initials: \textbf{LP}~=~Leonardo Palanca, \textbf{SP}~=~Sebastian Pasz, \textbf{LM}~=~Lorenzo Mottinelli, \textbf{JM}~=~Johnny Magon.

\subsection{Phase 1 -- Bootstrap (April 18, 2026)}
The first day was about answering one question: \emph{can we get from ``a Fed statement exists on a webpage'' to ``it lives in a row in our database''?} LP set the visual and documentation tone -- a placeholder README, an architecture sketch, and an HTML mockup whose layout language survived every later iteration of the dashboard. SP built the Python side end-to-end in a single evening: requirements scaffolding, the first SQLite test harness, a scraper sandbox, the first \texttt{MonitorAgent} prototype, and the convention of keeping secrets out of the tracked tree. By the end of the day the loop worked end-to-end on a handful of statements, and the team adopted a commit-message style (descriptive subject, verified-by trailer) that held for the rest of the project.

\subsection{Phase 2 -- Architecture Consolidation (April 30, 2026)}
After a pause to clarify the brief, the focus shifted from ``does it run'' to ``does it have a contract''. LP rewrote \texttt{AGENTS.md} as a binding entry point for any future contributor -- human or AI -- and folded the architecture description into the README so the repository had a single source of truth for what each agent does. The most consequential move of the phase was operational rather than code: LP stood up \texttt{FakeFed}, a synthetic, statically served clone of the Federal Reserve website behind Nginx, so the scraper could be exercised end-to-end without touching the live Fed site. That decision paid off repeatedly later -- every fixture-driven test, every demo, and every accountability backtest runs against it. SP cleared dead files from the bootstrap day so the next phase started from a clean tree.

\subsection{Phase 3 -- Analyst v1 and Macro Ingestion (May 5--13, 2026)}
With ingestion stable, the next question was how to turn raw text into a number. JM shipped the first end-to-end \texttt{AnalystAgent}: segment each FOMC document into rhetorical sections (assessment, outlook, policy stance, voting record), ask an LLM to fill a structured rubric per section, write the result back into \texttt{sentiment}. LP introduced \texttt{OpenRouter} as a vendor-agnostic LLM gateway so the team could swap between Anthropic, OpenAI, and DeepSeek backends without code changes, and shipped the first FRED macro ingestion -- a \texttt{macro\_data} table plus a backfill command for CPI, core CPI, unemployment, and the 2-year yield. The lesson of this phase was that the monitor had to be source-agnostic: LP refactored it mid-May so the same code path ingested both the live Fed site and \texttt{FakeFed}, which removed the last temptation to write differential parsing logic.

\subsection{Phase 4 -- Multi-Analyst, Strategist and Automation (May 19--22, 2026)}
The team intentionally produced several competing analyst implementations rather than committing to one early. SP shipped two ``better analyst'' iterations exploring alternative segmentation strategies and prompts; JM added a \emph{dual-model} analyst that runs two LLMs in parallel and reconciles their outputs. Each variant writes to its own sentiment table (\texttt{sentiment}, \texttt{sentiment2}, \texttt{sentiment3}), and all of them survive in the production tree as testing baselines -- the weight-aware \texttt{w\_agent.py} that became the production analyst was selected on the strength of being able to tune section weights without re-running the LLM. JM fixed a weighted-score bug along the way where zero-weighted sections were polluting the average and biasing short documents toward neutral; that fix is the reason the current scoring formula explicitly excludes zero-scored sections from the average. LM shipped the first real \texttt{StrategistAgent}: EWMA-smoothed tone fed through an ordered-probit nowcast, with the divergence sign convention pinned (positive means the market prices a higher next rate than the tone model) and the FOMC historical-page backfill (back to 1994) moved into \texttt{scripts/} so a fresh install can rebuild the full corpus reproducibly. SP wired the whole pipeline onto cron with a bash wrapper layer, a 90-day rolling refresh window, and a sequence of glue scripts; JM added the final ``run-everything'' orchestrator that closed the loop.

\subsection{Phase 5 -- Productionization and Ops (May 22--27, 2026)}
The fifth phase was about turning a working prototype into a service. LP replaced the static \texttt{snapshot.json} that originally powered the dashboard with a live read-only FastAPI service and gave the data explorer the labels and legends it needed to be self-explanatory. LM backfilled \texttt{FEDFUNDS} into \texttt{macro\_data} to unblock the strategist's tone-implied-rate calculation, and JM aligned \texttt{db/schema.sql} with the multi-weights analyst.

The defining incident of this phase was a schema-drift bug discovered the same week: two SQLite copies of the production database had silently drifted, with the API reading a complete \texttt{/opt/FEDWatcher/fedwatcher.db} while every cron writer was updating an incomplete \texttt{/home/programming/FEDWatcher/fedwatcher.db}. The fix -- merging the two databases, repointing the API at the cron-written copy, and archiving the redundant tree -- is unremarkable; the policy change is what matters. LP tightened \texttt{AGENTS.md} so that any contributor must treat \texttt{db/schema.sql} as authoritative and must explicitly flag missing tables or columns rather than silently introducing them. That contract has been honoured in every subsequent schema change.

\subsection{Phase 6 -- Live Dashboard, Strategist Automation and the Accountability Experiment (May 27 -- June 2, 2026)}
LP swapped the v1 prototype dashboard for a live v2 dashboard wired directly to the FastAPI service. LM put the strategist on a 5-minute cron loop so each new statement triggers a fresh signal write, and JM landed a first attempt at a publicly visible track record: an \texttt{accountability} FastAPI router exposing hit rate, MAE, and Brier score over the strategist's ordered-probit signals. Two methodological issues surfaced almost immediately and were fixed by JM in a follow-up commit. First, the original code diffed \texttt{policy\_rate} around the meeting that had just happened, but the bucket probabilities target the \emph{next} meeting, so each forecast \(S(M)\) was re-anchored to \(S(M{+}1)\) and the realised outcome was read from \texttt{FEDFUNDS} around that anchor month. Second, intermeeting and emergency statements (gap to the previous statement below 35 days) were filtered out of both the forecast and anchor positions, since they cannot fairly be graded against a model that targets scheduled meetings. LP added the academic-report draft and the dashboard footer linking to it; LM produced a math review of the report and unblocked the LaTeX build by adding \texttt{lmodern} and correcting a math-mode escape in the methods section.

\subsection{Phase 7 -- Design Pass, Deploy Refactor and Accountability Rollback (June 7, 2026)}
The seventh phase was the design crystallisation pass. LM brought a full proposal design live in a single day -- a §04 Method modal, a §05 Accountability section with KPI tiles and a recent-predictions table, additional hero-takeaway modals, a back-to-top control -- and wired §05 to \texttt{/api/accountability} so the hardcoded placeholder numbers were replaced by live values. LP and JM repalettised the signal-divergence chart from green/red to two shades of purple, untangling the directional connotation of red/green from the tone-vs-market gap the chart actually shows. On the ops side LP introduced a deploy script using a restricted \texttt{programming} user with SSH connection multiplexing and realigned the backend deploy path with the \texttt{systemd} runtime tree, which made every later deployment a single command instead of a checklist.

The accountability section was then \emph{removed} from production later the same day, in two commits by JM: the router was unmounted from \texttt{main.py}, and the §05 block, the navbar link, and the corresponding fetch logic were stripped from the dashboard. The reason is documented in the strategist's own source: the ordered-probit \(\beta\) coefficients and cut points are explicitly flagged as ``placeholders calibrated to economic priors\ldots{} but MUST be refit on historical FOMC outcomes before being published'' (\texttt{agents/strategist.py}, lines 25--29). Publishing hit rates and Brier scores against an unfitted model would have advertised numbers that reflect prior beliefs rather than measured performance. The code was preserved (\texttt{app/accountability.py}) so the same metrics can be brought back online unchanged once the strategist is refit on the historical corpus.

\subsection{Phase 8 -- Pipeline Hygiene, AI Copy and the Final Local Launcher (June 8--12, 2026)}
The closing phase had no single objective; instead it tied off the loose ends so the project could be handed in as a coherent whole. \textbf{Pipeline scope} was narrowed across the entire codebase: LM removed minutes and speeches from the ingestion, scoring, and weights logic so the production path is unambiguously statement-only, and updated every reference -- in the analyst variants, the monitor, \texttt{run.py}, and \texttt{update\_weights.py} -- to match. \textbf{The FRED monitor} was hardened by SP in three iterations: handling missing months by averaging adjacent observations, projecting one forward proxy month so the strategist always has a row for the latest document, and rationalising the \texttt{FEDFUNDS} column naming to use the existing \texttt{policy\_rate} field.

\textbf{The narrative pipeline} -- the AI-generated hero and §02 Breakdown copy -- was completed by LM. The deterministic accountability and snapshot endpoints were already in place; what was missing was a layer that turned those numbers into prose. LM shipped \texttt{/api/narrative} with a system prompt explicitly bounded to ``write prose, do not invent numbers'', a process-wide cache keyed by latest signal id, and a deterministic fallback when no OpenRouter key is present. The dashboard was then taught to render the AI copy directly into the existing layout, with hawkish/dovish/neutral consistently italicised and rendered in the project palette. \textbf{FakeFed} graduated from a static fixture into a managed surface: LP added password-guarded \texttt{POST}/\texttt{DELETE /api/fakefed/statements} endpoints so synthetic statements can be published or removed from the dashboard side without manual file edits, then closed the loop by making file deletion cascade to the corresponding \texttt{documents}, \texttt{sentiment\_w}, and \texttt{signals} rows. JM split the README into a conceptual document and a hands-on \texttt{USER\_GUIDE.md} so new contributors have a single entry point for installation, the FastAPI surface, and the FakeFed workflow.

\textbf{Several small lessons from earlier phases compounded into structural fixes.} The recurring problem of popups colliding with the sticky topbar was solved by pinning every \texttt{.modal} and \texttt{.popover-overlay} below the topbar safe zone, rather than overriding individual modals. Interpolated rows in the §03 macro\_data table were highlighted in the palette yellow with an explicit legend, so a reader can tell at a glance which months are FRED data and which are the strategist's adjacent-month average. LM closed the phase by aligning \texttt{run.py} with the README architecture end-to-end: \texttt{python run.py pipeline --once} now runs the full chain (FRED $\rightarrow$ MonitorFed $\rightarrow$ FakeFed (optional) $\rightarrow$ Analyst $\rightarrow$ Strategist), with a \texttt{--rescore} flag for full signal regeneration and a DB migration script (\texttt{scripts/migrate\_db.py}) that brings older databases up to the current schema without losing data. \textbf{The state at hand-in is the state a new contributor reaches by running a single command on a clean machine.}

\subsection{What we kept and what we set aside}
Across the eight weeks the team kept a small, stable toolchain: \textbf{Python 3} (FastAPI, \texttt{requests}, \texttt{beautifulsoup4}, \texttt{pandas}, \texttt{sqlite3}), \textbf{SQLite} for storage, \textbf{Nginx} and \texttt{systemd} on the VPS, and \textbf{vanilla HTML/CSS/JS} (Chart.js) for the dashboard, deliberately avoiding a frontend framework. Generative-AI tools and their usage are documented in Section~\ref{sec:ai}.

The most important decisions the team did \emph{not} make are also worth recording. The legacy analyst variants were never deleted -- they remain in the codebase as testing baselines, since the choice of \texttt{w\_agent.py} as the production analyst depended on their existence as comparison points. The accountability router was not deleted when the §05 section was removed from production; it remains ready to be re-enabled once the ordered-probit model is refit. ECB support remained a stretch goal and was never started: every hour spent on it would have been an hour not spent calibrating the model that actually powers the dashboard. These omissions are what made the eight-week schedule survive contact with reality.
